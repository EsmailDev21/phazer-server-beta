## What 3.8 did (editor + diff)
Schema: `TemplateDraft`, `Template.nodeKeySeq`; migration `20260623000000_step_3_8_template_drafts`. New pure `src/templates/diff/` and `src/templates/editor/editor.apply.ts`; `TemplateEditorService` (draft, patch, publish, discard, draft diff); `TemplatesService.addVersionInTx` (the version route and publish share it) and `diffVersions`; 7 routes; the key counter also seeded by create/addVersion. Details: "Editor and diff (step 3.8)" in `docs/design/blueprint-v1.md`.
Verified: **1054 unit tests pass (28 skipped)**, typecheck + `nest build` clean, **integration in the sandbox: 314 passed, 1 skipped** (Prisma 7 + local Postgres 16, NOT the pinned 5.22 stack: run `npm run test:integration` on docker compose). New: 23 diff unit tests, 29 editor unit tests, 19 editor integration tests.
What the tests prove: DIFF - complete (every single-step change anywhere in all three golden fixtures, ~hundreds each, shows up), symmetric (diff(B,A) is diff(A,B) turned around, over all of them), `identical` <=> canonical JSON equal over random multi-step edits, summary adds up, deterministic, never throws on corrupt documents. EDITOR - identity (rename/update/move/reorder never change a key; the diff shows modified/moved/reordered, never added/removed), keys minted are unique, new and never reused (also across discard/publish/delete), atomic (input never touched, failed op leaves nothing), every accepted result validates and every rejection is structured (fuzz: 3 fixtures x 250 rounds x 4 batches, both paths exercised), prototype-name/garbage ops never throw. DB - revision protocol under real concurrency (8 writers same revision: one wins; 6 retrying writers all land with unique keys), failed batch spends no key, publish is one transaction (racing publishes/publish-vs-patch/stale base/no changes), counter survives discard, edited template applies (including a file attached through the editor and copied by the apply).
Mutation-checked: input cloned, dependency cascade, cycle check, counter start, row lock, revision check, stale check, counter persistence, draft deletion on publish, diff: dropped entity kind, dropped order check - each failed a test. One equivalent mutant noted: skipping already-used keys in `mint` is unreachable (the counter always starts past the highest n<k>), kept as a second line of defence.
Behaviour worth knowing: moving a task between projects needs `clear:["status","iteration"]` when the workflows differ (otherwise validation refuses, by design); a template created from the API cannot declare files until they are uploaded (3.7), and the editor's `addAsset` is how they get into a version.
NOT run: prettier/lint, real stack, HTTP-level tests of the routes.
