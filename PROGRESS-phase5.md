## 5.15 Phase B, part 2: WAIT, a durable delay (done)
- **WAIT {for: {amount, unit}}**: the run stops; what is left of it is saved (a SNAPSHOT of the rule's actions plus the position in the tree: each enclosing list, where to carry on, the run context incl. current task and captured variables) in `automation_waits`; a job every minute carries on what is due, as its own run row (`eventId wait:<id>`). Works at top level, in IF/else-if branches, in WITH and in SCHEDULE rules; may wait again. Refused inside a loop (`WAIT_IN_LOOP`) and inside a rule that is called by another (`RUN_RULE_HAS_WAIT`); both also refused at run time.
- Resumes only if the **rule is still on and the task still exists** (else CANCELLED with the reason). **At most once**: atomic claim + a unique run row per wait (two independent guards; a stuck claim is marked FAILED after an hour, never re-run). Not counted against the rule's per-minute run allowance. Configurable: `AUTOMATION_MAX_WAIT_DAYS` (30, ceiling 365), `AUTOMATION_MAX_PENDING_WAITS` (5000, ceiling 100000). Admin: `GET .../automations/:id/waits`, `DELETE .../waits/:waitId`.
- **Migration** `20260701000000_step_5_15_automation_waits`: enum `automation_wait_status`, table `automation_waits` (FKs: rule CASCADE; run and task SET NULL).
