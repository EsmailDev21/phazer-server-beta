# ADR-0013 - Slack adapter: slash command, shortcut, modals, unfurl, notify

Status: ACCEPTED (step 2.5). No owner fork was raised: the spec fixes the surface, the app is product-owned (as in ADR-0012), and the command executor already exists.

## Context
Slack differs from Discord in ways that matter: three separate request URLs, HMAC signing instead of Ed25519, replies that choose public/private per message, modals that must be opened by an API call inside a 3-second window, and a link-unfurl event that shows content to a whole channel.

## Decisions
1. **Product-owned Slack app** (`SLACK_CLIENT_ID/SECRET/SIGNING_SECRET`); `docs/slack-app-manifest.json` creates it in one paste (slash command, message shortcut, interactivity, `link_shared`, redirect URLs, scopes).
2. **Three signed routes** (`@PublicSigned`, flag INTEGRATIONS): `POST /integrations/slack/commands` (form), `/interactivity` (form field `payload` = JSON), `/events` (JSON). `X-Slack-Signature` = `v0=` HMAC-SHA256 of `v0:timestamp:RAW body`, constant-time compared, timestamp window 5 minutes (a correctly signed old request is a replay). Checked FIRST: nothing is read, written or enqueued for an unverified caller; a missing/short `SLACK_SIGNING_SECRET` rejects everything. `url_verification` is answered only after verification, with the challenge string only. The verifier passes Slack's own published example.
3. **Response model.** The HTTP answer is an empty 200; the real answer is posted later through the payload's `response_url` by the shared `chat.command` job. Slack lets every post pick `in_channel` or `ephemeral`, so: `create` and message-to-task are public, everything else and every error is private (better than Discord, where the choice is made at the ack). Dedupe by `trigger_id` (events: `event_id`), so Slack's retries are harmless.
4. **Modals.** The shortcut / "Set due" button must call `views.open` with the `trigger_id` within 3 seconds, so that one call is made synchronously (DB reads + token + Slack). A failure is explained privately. A modal submission has NO `response_url`: its result is posted by the job (public: `chat.postMessage` in the message's thread; private: `chat.postEphemeral` to the user), and validation problems (empty title, bad date, "already created", no permission, not linked) are returned as `response_action: errors` INSIDE the modal. A modal submission only looks the user up (`lookupLinkedUserId`): it never issues a link token.
5. **Grammar.** `/task create Fix login project:"Web app" due:2026-12-31 priority:HIGH @alex`, `update KEY ...`, `assign KEY @alex`, `list [mine] [project:...]`, `link workspace:KEY [project:...]`, `help`. Words + `key:value` pairs, quoted values, straight or smart quotes. Mentions arrive as `<@U123>` only with "Escape channels, users, and links" on (`should_escape: true` in the manifest).
6. **SSRF guard.** `response_url` is attacker-influenced input that we POST to. It must match `https://hooks.slack.com/(commands|actions)/<id>`: checked when the request is accepted AND again inside the adapter; anything else is refused or falls back to posting to the channel with the bot token.
7. **Output is never trusted.** Slack treats `& < >` as markup (`<!channel>`, `<@U1>`, `<https://evil|click>`). Every user-originating string is escaped first and only then do our own `**bold**` become `*bold*`, so a task titled `<!channel> ...` is stored verbatim but cannot ping a channel or forge a link. Messages never unfurl.
8. **Unfurl (`link_shared`).** A pasted task URL becomes a task card. An unfurl is visible to the WHOLE channel, so it is shown only for a task the person who PASTED the link may see: poster linked, task in this connection's account, visible to them. Anything else unfurls nothing and never produces a "link your account" prompt for a link someone merely pasted. URL matching is the strict inverse of `taskUrl()` (whole URL, no query tricks, at most 5 per message). Runs as the `chat.unfurl` job.
9. **`/task link`** needs the caller to be a Slack workspace admin/owner (`users.info`, called ONLY for this intent) and a workspace admin in the app (`linkChannel`). Slack team id is the GUILD link's tenant id.
10. **Message -> task.** Shortcut `create_task` opens a modal (title = first line, description = the message with mentions/links flattened to plain text); the submit creates the task and an `ExternalLink` (`MESSAGE`, or `THREAD` for a thread root) in one transaction. The link URL is `https://slack.com/app_redirect?team=..&channel=..&message_ts=..`: always constructible without an extra API call, but that `message_ts` deep-links to the message is assumed from memory, not verified.
11. **Notify.** `chat.postMessage` with the connection token, a colour-bar attachment, `unfurl_links:false`. `ok:false` with channel_not_found / not_in_channel / is_archived / token_revoked / invalid_auth / missing_scope / account_inactive ... is `NotifyPermanentError` (it appears in the delivery log and disables the subscription after 3); everything else is transient. `chat:write.public` was added to the requested scopes so public channels work without an invite; private channels still need `/invite @app`. Installs made before this change must be reinstalled to get the scope.
12. **Reuse.** The 2.4 executor runs unchanged (new: `describeTask`, provider-aware wording). `ChatCommandPayload` gained an optional `reply` target; `chatReply` gained the connection token for posted replies. No schema change, no migration.

## Found by the tests
- A task with no priority crashed the unfurl card (fixed; null-safe now).
- A mutation (unfurl ignoring the poster's visibility) SURVIVED the first test set because it only covered another account's task; a same-account, project-restricted case was added. The same shared executor guard now has a test for the slash command too.

## Not done
Enterprise Grid (`enterprise_id`); `app_uninstalled` / `tokens_revoked` events (the connection stays ACTIVE until a call fails, then notify errors surface); unlink and comment commands; custom workflow statuses (the 5 categories only); the manifest's `unfurl_domains` must match the web app host by hand. Nothing was run against real Slack: payload shapes, `views.open`, `chat.postEphemeral`, `chat.unfurl` and the scope list follow the documentation and are tested with signed fixtures and mocked HTTP.
