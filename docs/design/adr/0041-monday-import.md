# ADR-0041 - monday.com connector and importer (step 4.11)

Status: Proposed by the builder; every decision names its alternative. Follows ADR-0036 (ClickUp), ADR-0039 (Asana) and is the first consumer of ADR-0040 (field roles).

## How the research was done (and what it is worth)
No monday account, app or API response was available. Shapes come from monday's public documentation (developer.monday.com: OAuth, the OAuth 2.1 migration guide, rate limits, API versioning, boards / items / items_page / next_items_page / updates / assets / column-type references) and third-party clients. **Every shape below is unverified against a live response.** Fixtures are synthetic. First live run: record real responses and add a contract spec (like Linear's).

### Where this corrects the handoff
1. **There are TWO OAuth flows, not "tokens that never expire".** The *legacy* flow: non-expiring token, no refresh, no revocation, no PKCE. The *OAuth 2.1* flow (selected per app *version* in the Developer Center): PKCE (S256) required, expiring JWT access tokens (about a day), **rotating** refresh tokens, a different token endpoint, a revocation endpoint. The adapter supports both (`MONDAY_OAUTH_FLOW`, default `2.1`, must match the app version).
2. **The limit that bites is the DAILY call cap by plan** (Free 200, Standard 1,000, Pro 10,000, Enterprise 25,000; per account, per app; resets 00:00 UTC), not only the complexity budget (5M points a minute, a minute request cap by plan, a concurrency cap, an IP cap). A Free account cannot import a real board.
3. **Application errors come back as HTTP 200 with an `errors` array**; a 200 is not success. Rate limits are HTTP 429 with `Retry-After` and `retry_in_seconds`.
4. **Cursors live 60 minutes from the first request and are never extended** (confirmed): a big board can outlive its cursor mid-import.
5. **The API version must be pinned.** A request without `API-Version` silently floats to Current; versions rotate quarterly (2026-10 became Current on 2026-10-26, 2026-07 is Maintenance).
6. `public_url` of an asset is valid for **one hour** and is different on every query.
7. `FieldType` has no email / phone, and canonical comments support one level of replies (monday's updates -> replies map exactly).

## Decisions
1. **A connection is the monday ACCOUNT** (a person belongs to several and picks one on the consent screen). `externalAccountId` = `me.account.id`, read right after the token exchange. *Alternative:* the user (rejected: one person, several accounts, each with its own plan and limits).
2. **Both flows.** `usesPkce` = flow is 2.1 (PKCE parameters are not sent in legacy). Legacy: JSON token body, no expiry, no refresh, revoke is a no-op. 2.1: form body, expiry from `expires_in` (number or string) else the JWT's `exp`, a rotating refresh token (the caller serializes refreshes under the per-connection lock, as for Jira), revoke posts the refresh token. *Alternative:* 2.1 only (rejected: the app version decides, and many existing apps are still legacy).
3. **Version pinned** to `2026-07` by default (`MONDAY_API_VERSION`), sent on every call. Moving it is a deliberate change with the "Unverified" list below as the checklist.
4. **Transport (`MondayClient`).** Every query also asks `complexity { query before after reset_in_x_seconds }` (free); when the remaining budget is under 150k points the next call waits for the reset (capped at 60 s) instead of provoking `COMPLEXITY_BUDGET_EXHAUSTED`. Errors: 401 or "not authenticated" -> `ProviderAuthRejectedError`; daily limit -> `ProviderRateLimitedError` until 00:00 UTC (the executor pauses the job and resumes by itself); complexity / concurrency / IP limits -> `ProviderRateLimitedError(retry_in_seconds)`; an expired cursor -> `MondayCursorExpiredError`; 403 / 404 about one object keep their status. The token is sent bare in `Authorization` (monday's documented form).
5. **Preview tells the truth about cost.** `estimate` computes the calls the import needs (about three per 100 items with comments / files) and compares them with the plan's daily limit (`account { plan { tier } }`): `DAILY_LIMIT` above 80%. A failing plan lookup never fails the preview.
6. **Tree: workspace (not selectable) -> board (selectable).** The main workspace (no id) gets a synthetic node `main`. Subitem boards and docs (`type != board`) are not offered. Folders are flattened (backlog #24). Each board node carries its `fields` for the picker (ADR-0040).
7. **The status is chosen, not guessed blindly (ADR-0040).** Status-typed columns offer `status` + `priority`; dropdowns `priority`; people `assignee`; dates `due` + `start`; **a timeline is split into two virtual fields** ("(start)" -> start, "(end)" -> due) because one field never plays two roles; the board's **group** is offered last as a virtual `status` candidate, so a board with no status column falls back to its groups. A board whose status is a column gets its labels as `UNKNOWN`-category statuses (the mapping step judges the names and shows them as guesses) plus a certain "No status"; a group-driven board gets one status per group. The timeline half nobody mapped becomes a date custom field, never lost. When the status is not the group, the group becomes a tag `Group: <title>` so the board's structure survives.
8. **Items are read 100 per page** (`items_page` / `next_items_page`, up to 500 allowed) with nested column values and subitems. **A page is split** when parents + subitems would exceed 1,000 tasks: the cursor keeps `skip` and the same monday cursor, so the page is re-read and continued (tested: 12 parents x 150 subitems, nothing lost or repeated).
9. **A dead cursor is rebuilt, not fatal.** The cursor stores `pos` (items before the current page). On the expiry error the walk restarts with id-only pages (same size, so boundaries line up) up to that position, then reads the real page: a few cheap calls instead of a failed import. A first-page request can never be "expired" (the error surfaces).
10. **Subitems** live on a hidden board with their own columns, so they are read by column TYPE: status label -> the parent board's status of the same name (the default labels match), first people column -> assignee, a date or a timeline -> due (and start). Subitem comments and files are not imported (backlog #25).
11. **Comments and files cost one call per 100 items** (`items(ids:) { updates(limit: 100) { replies } assets }`), not one per item: the daily limit decides everything. Updates -> comments, replies -> comments with `parentExternalId`, oldest first, `body` HTML -> markdown with `text_body` as the fallback, empty ones dropped. More than 100 updates on one item are cut.
12. **Files.** `providerRef` is the opaque `monday-asset:<id>` (digits only), never an address. `fetchAttachment` asks `assets(ids:)` for a fresh `public_url` right before the copy, checks the host (https, no port / userinfo / IP, `*.monday.com` or a `monday*` S3 bucket, plus operator-added `MONDAY_FILE_HOSTS`), and fetches **without the access token** (a public URL is public; the token must not travel to storage). Anything else is refused before a request.
13. **Custom fields are shared by title + type** across boards (`cf:<hash of folded title>:<TYPE>`): columns are per board in monday, and a "Budget" number on ten boards should be one field, not ten. Options are the union. Mapped: text / long text / email / phone -> TEXT, numbers / rating -> NUMBER, date -> DATE, people -> USER, link -> URL, checkbox -> CHECKBOX, a status column that is not the workflow -> SELECT, dropdown -> MULTI_SELECT. Formula, mirror, connect-boards and the like are reported by kind and count; structural columns (name, subitems, files, dependency, creation log ...) are silent.
14. **Dependencies.** A `dependency` column lists the items THIS item depends on: blocker -> this, `BLOCKS`, one id per edge; an edge whose other end is not in the import stays pending and is dropped by the writer.
15. **Cursor** `{ plans[], i, cur, pos, skip }`, plain JSON. The per-board plan (chosen roles, valid status ids, label map, column -> field map, dependency columns) is decided ONCE on the structure page and travels in the cursor (a few KB per board, at most 200 boards). *Alternative:* re-read each board's structure when entering it (rejected: one more call per board against a daily limit that can be 200).

## Found while building (by the tests)
- With only one half of a timeline mapped, the other half **silently vanished**. It is now a date custom field.
- **Shared mapping patterns:** monday's default label "Working on it" was guessed as *To do*, and "Not started" matched `started` and was guessed as *In progress* (this also affected Asana sections). `NAME_IN_PROGRESS` now knows `working on it`, `wip`, `underway`, `ongoing` and no longer matches "Not (yet) started"; tests added in `mapping.tables.spec.ts`. Linear / ClickUp / Jira are unaffected unless an `UNKNOWN`-category status carries those names.
- The field-role picker (ADR-0040) needed no change for its first consumer; the "one field, one role" rule is what produced the virtual timeline halves.

## Unverified (list for the first live run)
**Auth:** bare-token `Authorization` for OAuth tokens (versus `Bearer`); token endpoint body formats (JSON for legacy, form for 2.1); the `scope` parameter on authorize and the scope names (`me:read account:read boards:read workspaces:read users:read updates:read assets:read`); `expires_in` or JWT `exp`; the revoke parameters; `me { account { id name } }`.
**Limits / errors:** the `complexity` root field and its four subfields in the pinned version; the exact error codes (`DAILY_LIMIT_EXCEEDED`, `COMPLEXITY_BUDGET_EXHAUSTED`, concurrency, IP, cursor) and whether the daily limit arrives as 429 or as a 200 body; `account { plan { tier } }` and the tier names.
**Data:** `boards(... state: all)` and `Board.type` values (`board`, `sub_items_board`, `document`); `items_count` (does it include subitems?); `workspaces` paging and the main workspace's shape (`workspace_id` null); `users(limit, page)` maximum and enforced pagination; `items(ids:, limit:)` with `updates(limit: 100)` and `replies`; the root `assets(ids:)` query and the real `public_url` hosts (the allow-list is a guess: watch the logs for a 400 "not a monday file host" and add the host to `MONDAY_FILE_HOSTS`); every column `value` JSON shape (status `index`, people `personsAndTeams`, date `date` / `time` in UTC, timeline `from` / `to`, dependency `linkedPulseIds`, checkbox `checked: "true"`, link `url`); `text` of a dropdown (comma-joined); status `settings_str` (`labels`, `labels_positions_v2`) and dropdown `settings_str` (`labels` as an array); subitems nested inside `items_page` and their column types; whether archived items / groups are returned; the cursor-expired error shape and that id-only page boundaries line up.

## Not done
Folders (flattened), docs, dashboards, automations, activity logs (history), formula / mirror / connect-boards columns, subitems' comments and files, multi-level board hierarchies, the tags column, `done_colors` as a category hint, archived items, board permissions, a `createPerSpace` for workspaces, an item "description" (monday has none: a long-text column is a custom field), comments beyond 100 updates per item.
