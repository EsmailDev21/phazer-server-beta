# ADR-0042 - Notion connector and importer (step 4.12)

Status: Proposed by the builder; every decision names its alternative. Follows ADR-0036 / 0039 / 0041 and is the second consumer of ADR-0040 (field roles).

## How the research was done (and what it is worth)
No Notion workspace, connection or API response was available. Shapes come from Notion's public documentation (developers.notion.com: authorization, create-a-token, the 2025-09-03 and 2026-03-11 upgrade guides, data sources, property schema / values, retrieve page markdown, search, request limits, the changelog) and third-party clients. **Every shape below is unverified against a live response.** Fixtures are synthetic. First live run: record real responses and add a contract spec (like Linear's).

### Where this changes the handoff
1. **The page body is one call, not a block tree.** Since API version **2026-03-11**, `GET /v1/pages/:id/markdown` returns a page's content as markdown (with `truncated` and `unknown_block_ids`). The converter the handoff called "new work" (recursive block walker) does not exist in this design; a small *enhanced-markdown -> our markdown* post-processor replaces it.
2. **API version decided: `2026-03-11`**, pinned and always sent. It is Current, it has the markdown endpoint, and its breaking changes only touch writes (`after` -> `position`) and the trash flag (`archived` -> `in_trash`, read under both names). A next version that makes the enhanced markdown the default is announced; a pinned version is not affected.
3. **A database is a container of data sources** (since 2025-09-03). The data source holds the properties and is what is queried; search returns data sources. The picker lists data sources; "database" never appears in the code.
4. **Tokens do refresh**: the token response carries a (nullable) `refresh_token`, it rotates, and there are revoke / introspect endpoints. But **no `expires_in` is sent** and the access-token lifetime is not documented (decision 3).
5. **`status` properties have groups** (To-do / In progress / Complete): a real, certain source of status categories (decision 5).
6. **Shared databases only is inherent**, not a limitation to decide: a connection sees what was shared with it; the empty state has to teach sharing (decision 7).

## Decisions
1. **A connection is the Notion WORKSPACE** the person authorized (one token per workspace; the token response names it). `externalAccountId` = `workspace_id`. OAuth: Basic auth on the token endpoint, JSON body, the redirect URI always sent, no PKCE (none documented), `owner=user`.
2. **Version and pacing.** `Notion-Version` is always sent (`NOTION_API_VERSION`). Notion allows an average of 3 requests a second per token: the bucket is 2.5 a second by default (`NOTION_REQUESTS_PER_SECOND`, 0.2-3). A 429 carries `Retry-After` in seconds (handled by the HTTP layer).
3. **Token lifetime is assumed, not known.** With a refresh token the access token is treated as expiring after `NOTION_TOKEN_TTL_SECONDS` (default 3600; 0 = never): refreshing a token that did not need it costs one call, not refreshing one that did breaks the connection. The refresh token rotates (the caller serializes refreshes under the per-connection lock, as for Jira and monday); a null answer keeps the stored one. *Alternative:* never schedule a refresh and react to a 401 (rejected: the executor treats a 401 as "reconnect", while a valid refresh token exists).
4. **Tree: a single non-selectable "Shared with this connection" node -> data sources** (search with the data-source filter, newest first, capped at 2,000). Each node carries its `fields` for the picker (ADR-0040): `status` -> status + priority, `select` -> status + priority, `multi_select` -> priority, `people` -> assignee, `date` -> due + start **and a virtual "(end)" field -> due** (a range's end), `checkbox` -> status (last, so a "Done" checkbox is the workflow only when nothing better exists). Field ids are PROPERTY ids (names are editable).
5. **Statuses.** A `status` property: each option takes the category of its group (To-do -> TODO, In progress -> IN_PROGRESS, Complete -> DONE) as a **certain** category (the mapping step shows them as HIGH confidence, unlike a guess); an option in no group is UNKNOWN. A `select`: options are UNKNOWN (judged by name, shown as guesses). A checkbox: "To do" / "Done". Always a certain "No status" for empty values. A renamed / re-created option still finds its status by folded name.
6. **Rows are read 25 at a time** (`POST /v1/data_sources/{id}/query`, sorted by creation time, `start_cursor`), because each row costs a markdown call and, with comments, a comments call: 25 rows are about twenty seconds of one bundle page at 3 requests a second. Trashed rows are skipped (`in_trash` or `archived`). `estimate` counts rows by paging the query with only the title property (and falls back to a plain query if the filter is refused), capped at 20,000 per source, and says how long the import will take.
7. **Empty state.** `SourceTree` gains an optional `hint`; an empty search returns `{ nodes: [], hint }` ("Nothing is shared with this connection yet. In Notion, open the database ..., use the ••• menu -> Connections ...") and the Select step shows it in place of "The source has nothing to import". Backward compatible (a tree without a hint behaves as before).
8. **Page text = markdown.** Converted by `convertMarkdown`: callouts -> quotes, toggles -> bold summary + body, tables -> GFM (pipes escaped), columns / synced blocks / mentions / table of contents lose their tags, `<unknown/>` is counted, **fenced code is never touched**. A truncated page is completed from the blocks it names (up to 5 more calls); anything still missing leaves the line "_(Part of this page could not be imported.)_".
9. **Files: the signed URL is replaced by the attachment's `providerRef`.** Notion's file URLs are pre-signed and expire in about an hour; the file copier re-points an EXACT `providerRef` string in descriptions and comments to our own copy after copying, so each file reference in the markdown becomes `[name](notion-file:<page>:<m|p>:<hash>)`. The identity of a file is the hash of its URL **path without the query** (the signature changes on every read). `fetchAttachment` re-reads the page (its markdown for `m`, its properties for `p`) to get a fresh signed URL, checks the host (https, no port / userinfo / IP, `notion.so`, `*.notion-static.com`, the `prod-files-secure` bucket, `s3.*/secure.notion-static.com/...`, plus operator-added `NOTION_FILE_HOSTS`) and fetches **without the access token**. Files that are only links (`external`) are not copied. Without file copying the references would dangle, so only the file's label stays.
10. **Comments** keep their **discussions**: the first comment of a discussion is the comment, later ones are replies to it (the canonical model has one reply level). Rich text -> markdown (annotations, links, mentions as text). A connection without the "read comments" capability simply gets none.
11. **Structural relations by NAME, only self-relations**: "Parent item" -> parent; "Blocked by" / "Depends on" -> blockers of this page; "Blocking" -> pages this one blocks (`BLOCKS`, one id per edge). A relation to another data source, or with another name, is reported as skipped. A relation holds at most 25 references in a page answer; the rest are not read.
12. **Custom fields are shared by name + type** across data sources (`cf:<hash of folded name>:<TYPE>`), options unioned (as in ADR-0041). Mapped: text / email / phone / unique id -> TEXT, number -> NUMBER, select / (unused) status -> SELECT, multi-select -> MULTI_SELECT, date -> DATE, people -> USER, checkbox -> CHECKBOX, url -> URL. Silent: title, files (-> attachments), timestamps, creators. Reported: formula, rollup, foreign relations, and the rest.
13. **Cursor** `{ plans[], i, cur }`, plain JSON; `cur` is the `start_cursor` USED for the current page, so re-sending it re-fetches the same page. The per-source plan (chosen roles, status ids, label map, property -> field map, relations) is decided once on the structure page.

## Found while building (by the tests)
- An attachment was named after its **caption** ("Design mock") instead of the file ("design.png"); it now prefers the file's own name.
- A truncated page whose missing block **was** fetched still got the "could not be imported" note; the note now counts only blocks that stayed unknown.
- Notion's signed URLs differ on every read, so any identity built from the whole URL breaks: the mutation that includes the query fails seven tests.

## Unverified (list for the first live run)
**Auth:** Basic auth + JSON body on the token endpoint; `redirect_uri` always sent (Notion's rule depends on how many are registered); the revoke endpoint and its body; whether access tokens really expire (and after how long), and whether the refresh token rotates on every use.
**Data:** `POST /v1/search` with `filter: { property: "object", value: "data_source" }` and its sort; the data source object (`properties`, `title`, `in_trash`); `filter_properties` as a repeated query parameter on the query; the query's `sorts` by `created_time` and the April 2026 pagination change; `GET /v1/users` (`person.email` only with the user-information capability); `GET /v1/comments?block_id=<page>` (`discussion_id`, `rich_text`); property value shapes (`status`, `select`, `date.end`, `people`, `files` with `type: file | external`, `unique_id`, `relation`).
**Markdown:** the exact syntax of the enhanced markdown (the tag names `callout`, `details` / `summary`, `table` / `tr` / `td` and `header-row`, `columns`, `image` / `file` / `pdf` / `video` / `audio` with `src`, `unknown`, mentions, synced blocks); whether file URLs inside it are signed S3 URLs on `prod-files-secure` or another host (the allow-list is a guess: watch the logs for a 400 "not a Notion file host" and add the host to `NOTION_FILE_HOSTS`); that `truncated` / `unknown_block_ids` follow-ups by block id work on `/pages/{block_id}/markdown`.

## Not done
Views, templates, the content of nested child pages and inline databases, formula / rollup **values**, relations other than Parent / Blocked by / Blocking, page / user mentions as links, comment attachments, history, per-source "skip the page text" (a large source costs one call per row), a rate-aware scheduling of very large imports.
